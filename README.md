# RYM cross-check

A Windows C++23 CLI that finds songs in RYM's top all-time chart which are absent from a local MP3, FLAC, or M4A library. Exact matches and a TOML whitelist are excluded; uncertain matches remain in a Markdown report for review.

## Build

Requires x64 MSVC with C++23 support, CMake 4+, Ninja, and an AVX2-capable CPU for the Release build. The supplied helper discovers the installed Visual Studio toolchain automatically.

```powershell
./scripts/build.ps1 -Action all -Preset release
./scripts/build.ps1 -Action all -Preset debug
```

From an x64 Visual Studio developer terminal with CMake/Ninja on PATH:

```powershell
cmake --preset release
cmake --build --preset release --parallel 8
ctest --preset release
```

Dependencies are downloaded from pinned upstream archives, checked with SHA-256, and built statically with a shared MSVC runtime. Downloads remain under `build/downloads`; generated dependencies, binaries, and logs stay under `build`. No vcpkg installation is required.

## Run

```powershell
./build/release/bin/rym-crosscheck.exe --music-dir 'PATH/TO/MUSIC'
```

The default is `--top 200`, `--output missing.md`, and `--whitelist whitelist.toml`. The music path is always required. Run `--help` for concurrency, pacing, threshold, cache, and browser options.

```powershell
./build/release/bin/rym-crosscheck.exe --music-dir 'PATH/TO/MUSIC' --top 500 --output reports/missing.md
./build/release/bin/rym-crosscheck.exe --music-dir 'PATH/TO/MUSIC' --offline --top 200
```

Live mode collects chart and song pages in headless Edge using hidden browser targets and a dedicated profile with extensions disabled. Retrieval creates no visible windows or tabs. Verification cookies stay in that profile, and retrieval uses the same browser identity as visible verification. If RYM challenges the session, the CLI opens ordinary Edge without remote debugging: complete verification, then press Enter in the terminal or close that window. The CLI closes its owned verification browser and resumes hidden retrieval using the same profile's cookies. Verification is never solved automatically. RYM can still reject a session; incomplete charts never replace the previous report. A current Edge version supporting hidden CDP targets is required.

`--browser-profile PATH` overrides the dedicated profile location. `--private-browser` uses a fresh, isolated temporary profile, which is deleted after the run. This provides session-only cookies while allowing the verification window and hidden retrieval to share them; it uses ordinary Edge rather than Edge's InPrivate context. The default persistent profile retains cookies. `--web-mode http` uses direct HTTPS and fails clearly when RYM blocks it. Offline mode uses only a complete snapshot generated by a previous live run. Manual HTML/CSV import is not supported.

An absent default whitelist is empty. To create one, copy `whitelist.example.toml` to `whitelist.toml` and replace its example entries. Entries identify a song by RYM URL, or by `title` and `artist`/`artists`. Full collaboration credits are required for confirmed ownership.

`whitelist.toml` is personal configuration and is ignored by Git; the example file is included in the project. Build output, dependency downloads, caches, the default report, and editor settings are also ignored.

## Report and matching

The report contains linked song titles, artists, associated albums, status, and up to three possible local matches with similarity scores and relative paths. Scores describe string similarity, not probability. Album differences do not affect ownership.

Normalization ignores case, Unicode representation, spacing, typographic quotes/dashes, and explicit remaster suffixes. Accents, other punctuation, and live/remix qualifiers remain significant. Tags are preferred; missing fields fall back to `Artist - Title` filenames.

Exact matching uses Boost flat hash tables. Fuzzy matching uses Unicode trigram multiset indexes and length bounds followed by bounded Levenshtein scoring. Default thresholds are 90% artist and 85% title. Credit gaps are explicitly labeled and never imply ownership. Duplicate local editions occupy one suggestion slot.

Exit codes: `0` completed, `1` fatal error/cancellation, `2` completed with an incomplete local scan. Missing/review rows alone do not produce an error.

## Caches and cleanup

The working-directory `.rym-crosscheck-cache` stores versioned tag and chart records. Unchanged files reuse cached tags. `--clear-cache` removes application cache records before the requested comparison. Records older than 30 days are removed and application records are capped at 128 MiB.

Temporary output files are removed on controlled exit paths. Reports are replaced atomically. Windows jobs own the launched browser processes; only those browser instances are closed. Browser HTTP cache is cleared on teardown while normal-profile cookies are retained. Source/build files, music, whitelist, and personal browser data are preserved.

## Validation

CTest covers normalization, indexed/exhaustive agreement, current and synthetic RYM markup, whitelist, cache reuse, filename fallback, cancellation, atomic report preservation, and repeated-run handle cleanup. Debug tests additionally check CRT allocation differences across repeated runs.

The optional live UI regression check requires a previously verified dedicated profile; it exercises pagination and concurrent song retrieval while monitoring for new visible Edge windows:

```powershell
./build/release/rym-browser-visibility.exe 'PATH/TO/DEDICATED/PROFILE'
```
